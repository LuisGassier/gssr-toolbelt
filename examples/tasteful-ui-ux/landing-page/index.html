Walkthrough

Follow one decision, start to finish.

This is a single pull request moving through Kairos — not a metric, a record of the calls it made.

  1. 14:02

    Holds the merge. A PR touching billing/refunds.ts lands with two failing checks. Kairos blocks it and flags exactly which checks failed and why.

  2. 14:02

    Merges without asking. A second, unrelated PR is docs-only. Nothing here needed a human, so nothing waits on one.

  3. 14:03

    Escalates instead of auto-merging. Back on the billing PR, tests are green — but the diff still touches billing logic. Kairos routes it to a second reviewer, because the open question isn't "did it pass," it's "who should sign off."

  4. 14:04

    Promotes and watches. Once approved, Kairos ships staging → prod and watches the error rate for the next hour before marking the deploy stable.

That's the pattern: not a dashboard of green checkmarks, but a record of judgment calls, each made at the moment it mattered.
